# 简历管理与岗位匹配页优化设计

## 目标

在不改变现有模块划分和主要功能的前提下，升级简历条件配置与岗位匹配页：将条件改为受控单选，收紧准备信息和任务轨迹占用空间，让岗位结果成为页面主体，并让增量岗位匹配逻辑覆盖新采集或内容变化的全部职位。

## 交互与数据设计

- 简历条件：城市、工作经验、学历、薪资使用原生单选下拉；岗位关键词继续使用文本输入。
- 城市：使用上游 `city_codes.json` 的城市名称与代码，前端展示城市名、保存上游可接受的城市值。
- 条件枚举：经验为 `1-3年`、`3-5年`、`5-10年`、`10年以上`；学历为 `大专`、`本科`、`硕士`、`博士`；薪资为 `10-20K`、`20-50K`、`50K以上`。
- 匹配触发：先选择一份可参与匹配的简历，再启用按钮；请求仅处理该简历。首次显示“开始匹配”，完成一轮后显示“继续匹配”。
- 增量范围：新采集岗位以及已存在但岗位内容指纹发生变化的岗位进入本轮 LLM 评分，不再截断为 10 条。
- 活跃状态：结果项展示采集详情中的 `boss_active_status` 原始文本；“新活跃”仅包含“刚刚活跃”的职位。

## 页面设计

主题是个人求职者使用的本地岗位信号工作台，页面唯一主任务是快速选择简历、启动一轮匹配并阅读完整结果。

- 色彩：`#F7F5F2` 暖灰画布、`#FFFFFF` 内容面、`#2F2926` 主文字、`#5145C8` 操作紫、`#DCD7D2` 分隔线、`#17845B` 成功绿。操作紫用于白字按钮和普通文本时满足 WCAG AA 对比度。
- 字体：沿用系统无衬线作为正文与数据字体，标题使用现有字重体系，避免引入外部字体依赖。
- 布局：保留侧边导航和现有功能模块；匹配页顶部准备状态压缩为一条控制栏，简历选择与匹配按钮相邻；任务阶段压缩为“匹配信号轨”；结果面板占据首屏主体。
- 标志元素：匹配信号轨使用连续线连接检查、采集、过滤、评分、整理五个真实阶段，运行时只强调当前节点。
- 下拉：统一边框、内边距、箭头、悬停、焦点、禁用状态；保持原生键盘操作和移动端可用性。
- 动效：仅为信号轨当前节点和结果卡进入提供轻量过渡；遵守 `prefers-reduced-motion`。

## 测试与验收

- 单元测试覆盖内容变化检测、无 Top 10 截断、“刚刚活跃”筛选以及单简历触发。
- API 测试覆盖首次/继续匹配的数据流和结果字段。
- 前端通过静态检查、手动页面状态检查与响应式截图验收。
- 只做一次集中代码检查和一次最终验证，不进行多轮审查。
